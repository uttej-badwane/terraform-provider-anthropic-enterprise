# Anthropic Enterprise Provider

Manage an Anthropic organization (workspaces, members, invites, API keys, service accounts, workload identity federation, customer-managed encryption keys) and a Claude Enterprise organization (users, invites, RBAC groups, spend limits) through the Admin API.

Three credential classes exist. Each resource documents which one it needs.

The provider is published as `uttej-badwane/anthropic-enterprise` while its resource and data source types keep the `anthropic_` prefix. Declare it with the local name `anthropic` so Terraform associates `anthropic_*` types with it:

```terraform
terraform {
  required_providers {
    anthropic = {
      source = "uttej-badwane/anthropic-enterprise"
    }
  }
}
```

## Credentials

| Attribute | Environment variable | Header | Reaches |
|---|---|---|---|
| `admin_api_key` | `ANTHROPIC_ADMIN_API_KEY` | `x-api-key` | Console organization: organization, users, invites, workspaces, workspace members, API keys, external keys, rate limits |
| `oauth_token` | `ANTHROPIC_AUTH_TOKEN` | `authorization: Bearer` | Everything above plus service accounts, federation issuers, federation rules and workspace service-account memberships |
| `enterprise_api_key` | `ANTHROPIC_ENTERPRISE_API_KEY` | `x-api-key` | Claude Enterprise organization: users, invites, RBAC groups, RBAC roles, spend limits and increase requests |
| `compliance_api_key` | `ANTHROPIC_COMPLIANCE_API_KEY` | `x-api-key` | Compliance directory data sources (`anthropic_compliance_*`). Falls back to `enterprise_api_key` when that key carries compliance scopes |
| `analytics_api_key` | `ANTHROPIC_ANALYTICS_API_KEY` | `x-api-key` | Claude Enterprise analytics data sources (`anthropic_analytics_*`). Falls back to `enterprise_api_key` when it carries `read:analytics` |
| `api_key` (+ `workspace_id`) | `ANTHROPIC_API_KEY`, `ANTHROPIC_WORKSPACE_ID` | `x-api-key`, `anthropic-workspace-id` | Managed Agents control plane and Skills API (`anthropic_agent`, `anthropic_environment`, `anthropic_vault*`, `anthropic_deployment`, `anthropic_memory_store`, `anthropic_skill`). Beta; Admin keys are rejected there |

Only the credentials a configuration actually uses need to be set. A resource that needs a credential class which is not configured fails with a diagnostic naming the missing attribute.

No resource in this provider stores secret material in state: the Admin API cannot mint API keys, so `anthropic_api_key` only manages the name and status of keys created elsewhere.

## Example Usage

```terraform
terraform {
  required_providers {
    anthropic = {
      source = "uttej-badwane/anthropic-enterprise"
    }
  }
}

# Credentials fall back to ANTHROPIC_ADMIN_API_KEY, ANTHROPIC_AUTH_TOKEN and
# ANTHROPIC_ENTERPRISE_API_KEY when the attributes are omitted.
provider "anthropic" {}
```

## Schema

### Optional

- `admin_api_key` (String, Sensitive) Admin API key (`sk-ant-admin...`) created in the Claude Console. Reaches Console-organization endpoints: organization, users, invites, workspaces, workspace members, API keys, external keys, rate limits. Can also be set with `ANTHROPIC_ADMIN_API_KEY`.
- `analytics_api_key` (String, Sensitive) Claude Enterprise Analytics API key (`read:analytics`). Used by the `anthropic_analytics_*` data sources. Falls back to `enterprise_api_key`. Can also be set with `ANTHROPIC_ANALYTICS_API_KEY`.
- `api_key` (String, Sensitive) Regular workspace API key (`sk-ant-api03-...`) for the Managed Agents control plane and the Skills API (`anthropic_agent`, `anthropic_environment`, `anthropic_vault*`, `anthropic_deployment`, `anthropic_memory_store`, `anthropic_skill`). Admin keys are rejected by those endpoints. Can also be set with `ANTHROPIC_API_KEY`.
- `base_url` (String) API base URL. Defaults to `https://api.anthropic.com`. Must use `https`; `http` is accepted only for loopback addresses such as the bundled mock server. Credentials embedded in the URL are rejected. Can also be set with `ANTHROPIC_BASE_URL`.
- `compliance_api_key` (String, Sensitive) Compliance Access Key created in claude.ai (Data and privacy). Used by the `anthropic_compliance_*` directory data sources. Falls back to `enterprise_api_key`. Can also be set with `ANTHROPIC_COMPLIANCE_API_KEY`.
- `enterprise_api_key` (String, Sensitive) Claude Enterprise scoped API key created by a claude.ai organization primary owner. Required for RBAC groups, RBAC roles and spend limits. Also used for the Compliance directory and analytics data sources when the dedicated keys below are not set and this key carries the scopes. Can also be set with `ANTHROPIC_ENTERPRISE_API_KEY`.
- `max_retries` (Number) How many times to retry a request the API could not serve, such as a 429 or a 5xx. Defaults to `4`. Set `0` to attempt each request once and fail fast, which is often what a CI run wants. Can also be set with `ANTHROPIC_MAX_RETRIES`.
- `oauth_token` (String, Sensitive) An `org:admin` OAuth bearer token. Required for service accounts, federation issuers, federation rules and workspace service-account memberships; when set it is also used in place of `admin_api_key`. Can also be set with `ANTHROPIC_AUTH_TOKEN`.
- `request_timeout` (String) How long to wait for a single API request, as a Go duration such as `90s` or `2m`. Defaults to `60s`. Applies per attempt, so a run that retries can take longer than this in total. Can also be set with `ANTHROPIC_REQUEST_TIMEOUT`.
- `workspace_id` (String) Workspace to scope Managed Agents and Skills calls to (`wrkspc_...`), sent as the `anthropic-workspace-id` header. Required when `api_key` can access more than one workspace. Can also be set with `ANTHROPIC_WORKSPACE_ID`.
